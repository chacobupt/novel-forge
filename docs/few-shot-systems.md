# 两套few-shot系统：剧情回报与自然对白

## 剧情爽点：让案例参与设计决策

全书主线 → 卷级阶段变化与多线编织 → 完整单元 → 章内现场。few-shot在当前层级的实际缺口上起作用，不用相似句子替代完整故事。

原系统将检索与写作分成两个对象：

- `retrieval_profile`：故事层级、冲突引擎、POV、读者代入欲望、压力、选择、可见结果、持久改变、来源和准入状态。先过滤可生产样例，再按规范组去重。
- `prompt_payload`：命中后的完整故事转述、为何值得代入、预期/意外奖励、外部变化及不可迁移边界。排名、分数、来源坐标留在检索记录，不塞进小说。

三种故事层：独立欲望/冲突/结果线（BRANCH_STORY）、不同追求互相改变（WEAVE_RHYTHM）、多条铺垫与回报渠道汇成阶段改变（COMPOSITE_CLIMAX）。它们不同于八层模仿维度，也不同于所得强度等级。

轻量默认路线进一步缩短为按需一主一辅、两个真正不同构思、冷选及参照复核、完整故事、先详略后分章；修后检查回报是否被削弱。见 `reference/appeal.py`。

## 对话AI味：few-shot + 独立检索 + 适配审计

原独立检索链：目标场景/交流焦点 → Canonical去重 → ABC候选召回与排序 → 完整窗口Focused Audit → Structure/Surface能力判定 → 只投递允许学习的窗口与能力 → 正文与独立表达审核。

Structure看交流功能、双方目标、阻力处理、回应推进和状态变化。Surface看关系姿态、语域、说话策略、节奏、动作与台词因果以及可迁移声口。话题相同或措辞像，不自动适配。

`reference/dialogue_retrieval_production.py`、`dialogue_fewshot_gate.py`、`fewshot_reference_guarantee.py`保留召回、适配、降级与证据逻辑；需要使用者提供合法语料、标注、schema、运行配置和模型客户端。严格MATCH与PARTIAL/NEAREST等参考降级必须保留身份，不能混称严格通过。

解决对象包括摘要型对白、全员顾问腔、无动机讲课、名词压缩、动作对象关系错误、机械提醒和跨场功能重复。不是禁词表，不要求全员短句或互怼，也不鉴定作者身份。

## 当前路线与历史能力的关系

独立ABC检索器是已开发的系统模块；10月27日轻量默认路线使用单书有界窗口，不能说每次轻量写作都执行了ABC链。两条路线的输入、资产和验收应分别配置。few-shot用于解决设计与表达问题，但历史开发记录并不支持“所有AI味已根除”或固定效果提升百分比。
