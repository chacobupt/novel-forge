# 三层记忆与上下文提取

解决的核心问题是：长篇推进时主线、人物、资源、伏笔与近期动作不能随对话压缩而丢失，也不能把旧稿与候选误当成正式事实。信息外置，按寿命与权威分层，再按任务提取完整记录。

| 层 | 内容 | 更新边界 |
|---|---|---|
| M1 长期权威 | 书籍/卷罗盘、Canon、世界与力量规则、批准正文指针 | 候选不能反向覆盖批准事实 |
| M2 当前状态 | 单元故事、人物关系、对手行动、资源、期限、伏笔与开放线程 | 从已采用正文的实际变化提取 |
| M3 近期连续性 | 最近章节、章尾动作、必要声音、重复风险与近期回报模式 | 滑动窗口；仍有效状态上提M2 |

## 两条读取路径

1. 分层检索：读取来源，拆检索词与文本块，按查询覆盖/命中/标题排序，分配M1/M2/M3预算。旧实现曾按48%/32%/20%分配，块尾截断不保证结构化事实完整，适合探索定位。
2. 原子上下文：明确Artifact ID与JSON Pointer，核状态、用途可见性、来源SHA和隔离规则。必需记录整条进入，超预算直接报错；可选记录放不下整条跳过，记录遗漏。正式创作优先用这条路径。

原实现函数摘录见 `reference/context_compilers.py`。它依赖原项目的registry、task、policy等服务，不是独立可运行模块。可用的通用离线实现见 `tools/atomic_context.py`，它迁移了完整记录、来源校验、用途隔离和预算失败原则；不是对历史运行器的无缝替换。

## 从正文回到记忆

实际前章 + 本单元已采用分支状态 + 必要长期约束 → 当前写作包 → 正文 → 冷读/事实审核 → 带正文引文和SHA的状态差量 → 候选branch_memory → 下一章。

当前自主运行器的逐章分支回写与断点见 `reference/autonomous_production.py`、`reference/reader_known_state.py`、`reference/production_efficiency.py`。正式采用后的全局提交需要执行器落实权限、原子写入和回滚，提示词不能替代工程保证。
