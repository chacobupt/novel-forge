# 快速开始

## 1. 建立自己的书籍任务

复制 `templates/book.json`，填书名或代号、读者、题材、主角所求、想提供的体验、参照来源与预算。没确定的字段明确写未知，不沿用例子的故事设定。

## 2. 让总控形成候选方案

用 `tools/assemble.py` 拼装 coordinator 提示词。它只生成任务文本，不自动建立文件、调用其他模型或启动后台服务。将生成的文本交给你的 AI 助手；如果助手具备文件工具，给它一个专用书籍目录。

先拿到创意候选、书籍罗盘和全局资产候选。总控在已授权范围内可选稿；正式发布须有本书授权。不要一次生成全书逐章细纲。

## 3. 按角色推进一个单元

`planner`：给当前边界和参照分析，输出两个实质不同构思与选稿理由，再展开选中故事。

`writer`：给实际前章、候选事实、章故事、详略与相关角色卡，输出正文。

`reader`：新开独立上下文，只给必要前情和正文。不要给规划、作者自评或其他审稿结果。

`fact_checker`：另给正文、批准规则、候选状态及知识边界。

`reviser`：只处理有证据的问题；改完再交独立评审。严重构思问题返回planner。

`memory_keeper`：从采用正文提取有引文支撑的持续状态，禁止把计划写成事实。

`reference_analyst`：只按当前缺口读取你提供的参照，记录范围，分析可迁移条件，不照搬独特情节。

## 4. 先三章，再一个完整单元

三章用于观察叙述、理解与即时期待；完整单元才看发展、高潮、余波和连续性。冷读问题是：我盼什么？哪里兑现了？哪里想跳？为什么还想读？不要只问“打多少分”。

## 5. 保存输入和版本

每次保存角色、实际输入、输出版本、模型/配置、耗时、已知用量、裁决与证据。框架未提供用量时写未知。每次修稿保留父本，按任务累计预算，停止后记录具体下一动作。

`templates/` 是最小数据起点，不是强制每章填满的表格。参照窗口、完整正文和运行日志留在自己的工作目录，别提交到本仓库。

## 离线原子上下文示例

```bash
python3 tools/atomic_context.py --root . --manifest examples/context-manifest.json --purpose writer --max-chars 200 --output context-pack.json
python3 -m unittest discover -s tools -p 'test_context_tools.py'
```

该示例只验证完整记录、预算、权限和SHA；不代表运行了300万字长篇。预算统计记录内容字符，不含JSON封装或模型token。输出文件必须不存在。

原文读取器用`--source`、`--encoding`、`--sha256`、`--start`、`--end`定位合法自有来源；返回next_line用于补读，工具不声称已经语义理解。
