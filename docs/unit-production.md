# 单元级协作：一次任务推进一个完整故事

单元是一次创作任务、上下文交接和最终评审的主要边界。先构思完整欲望—行动—回应—改变—回报链，再作详略与章节安排，最后形成可连读的完整单元。避免每章重新规划造成任务碎片化、因果断裂和重复交接。

“单次写作”指一次单元任务持续完成交付，不等于一个模型调用输出整个单元。当前运行器 `write_unit()` 按章节顺序写作，每章接实际采用前章与分支状态，必要时有界修复，末尾再做完整单元连读。这样同时保留故事完整性与可恢复的小粒度执行。

任务累计预算、精确输入复用、已审前缀断点与按缺陷分层返修减少重复工作。历史一轮完整单元设计及一次局部修订约10分25秒；这是设计实测，不是正文速度，也不是普遍效率承诺。篇幅参考服从自然故事，不靠补水达到最低章数。

关键产物：concepts → selection → selected_story → allocation → chapters/versions/reviews → branch_memory → continuous_prose → unit_review/RESULT → NEXT_ACTION。输入/输出SHA、模型路由、失败与用量单独记录。独立冷读不见规划，事实核读另见约束。
